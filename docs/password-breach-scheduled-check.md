# 密码泄露定时检测与处置

## 功能说明

系统会为面板账户保存不可逆的密码检测指纹，不保存密码明文或完整 SHA-1。指纹由 HIBP 查询所需的 5 位 SHA-1 前缀，以及使用 `KVM_SECURITY_SECRET` 生成的完整 SHA-1 HMAC 组成。扫描时相同前缀只请求一次 HIBP k-匿名接口，再在本机对候选值进行 HMAC 比对。

- 独立设置项 `scheduled_password_breach_check_enabled` 默认开启，可由环境变量 `KVM_SCHEDULED_PASSWORD_BREACH_CHECK_ENABLED` 或系统设置持久化控制。
- 调度器 `password_breach_daily` 按宿主机本地时间每天 `00:00` 提交扫描；服务未运行而错过午夜时等待次日，不执行补跑。
- 系统设置的“立即执行”始终可以提交完整扫描，不受实时检测和定时检测开关影响。
- 同一时间只保留一个 `password_breach_scan` 任务，重复提交返回正在运行的任务 ID。
- 扫描更新使用“用户 ID + 当前指纹”作为条件，扫描期间已修改密码的账户不会被旧结果重新标记。

仅扫描已激活、未删除且已有指纹的账户。升级前账户会在首次 bcrypt 登录校验成功时登记指纹；定时检测已开启时会立即检测一次。HIBP 临时不可用时保留指纹并继续登录，留待后续扫描。

## 账户处置

| 账户类型 | 登录和会话 | 通知 |
|---|---|---|
| 管理员且未绑定 2FA | 首次发现时撤销现有 JWT；后续登录返回 403，提示运行 `sudo bash qvmc-manage.sh` 修改密码 | 首次发现向所有有效且邮箱已验证的管理员发送明细；每日定时任务发送未处理摘要 |
| 管理员且已绑定 2FA | 首次发现时撤销现有 JWT；登录必须完成 2FA，随后仅签发受限令牌并强制修改密码 | 同上 |
| 普通用户 | 可正常登录，每次登录成功后显示泄露警告，可立即进入 `/security?tab=password` | 首次发现后向该用户已验证邮箱发送一次；失败时后续扫描重试 |

邮件只包含用户名、角色、泄露次数、检测时间、2FA 状态和处理要求，不包含密码或哈希。SMTP 未配置或没有有效收件人时，仅记录中文日志，账户限制和概览异常状态仍然生效。手动扫描只发送本次新发现的首次通知，不发送每日摘要。

启用 `KVM_DEVELOPMENT_MODE=true`（或系统设置中的开发环境）时，登录流程会跳过上述管理员“泄露且未绑定 2FA”的登录锁定，和既有的登录二段验证、安全初始化及高风险验证绕过行为保持一致；账户的泄露状态仍会保留并返回给前端。

## 管理接口

| 接口 | 说明 |
|---|---|
| `GET /security/password-breach/status` | 返回开关、最近检查时间、运行中任务、泄露总数、管理员数、普通用户数及受影响账户处置状态 |
| `POST /security/password-breach/scan` | 提交完整正式扫描；兼容 API Key，并保留高风险二次验证；返回新任务或当前运行任务 |

任务中心使用 `password_breach_scan` 展示扫描进度，邮件投递任务使用 `password_breach_notify`。定时任务同时写入 `password_breach_daily` 调度事件，可在调度事件页查看成功或失败结果。

## 管理脚本改密

运行：

```bash
sudo bash qvmc-manage.sh
```

选择“修改管理员密码”，脚本只列出管理员账户，并要求隐藏输入两次新密码。脚本执行最小长度和 HIBP 检测；HIBP 服务异常时会显示警告并要求再次确认。修改成功后保留邮箱和 2FA，更新 bcrypt 与检测指纹，并清除泄露、通知和强制改密状态。

## 运维检查

1. 在系统设置关闭定时开关，确认午夜不创建任务，同时“立即执行”仍可使用。
2. 从任务中心确认重复点击复用同一运行任务，并查看失败详情。
3. 从概览确认泄露存在时状态横幅为异常且展示账户原因。
4. 管理员无 2FA 时使用脚本改密，确认旧会话失效且新密码可重新登录。
5. 管理员有 2FA 时确认验证后出现强制改密窗口；普通用户确认登录后出现可关闭警告。

本功能未增加新的系统或前端依赖。
