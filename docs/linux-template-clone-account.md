# Linux 模板克隆账户初始化

## 适用范围

适用于 Linux 模板的单台克隆、批量克隆和轻量云开通。模板使用 `nocloud` 初始化时，面板会在虚拟机首次启动前离线准备登录账户和密码。

## 账户处理规则

1. `template_user` 表示模板预期的旧普通用户名，服务端始终以模板元数据为准，不接受克隆请求覆盖。
2. 初始化会检查克隆磁盘内的真实账户；目标用户已存在时直接复用。
3. 目标用户不存在、旧模板用户存在且两者名称不同时，旧用户会被重命名为目标用户。
4. 目标用户和旧模板用户都不存在时，会创建目标用户、主目录和登录 Shell，并加入系统已有的 `sudo` 或 `wheel` 管理组。
5. 账户准备完成后才会设置目标用户密码。账户创建或重命名失败时，克隆任务直接失败，不会继续创建一个凭据不可用的虚拟机。
6. 只有目标用户明确选择 `root` 时，系统才会设置 root 密码并允许 root 登录。
7. 目标用户不是 `root` 时，系统会锁定 root 密码，并在 SSH 与 cloud-init 配置中禁止 root 登录；目标用户仍可通过 `sudo` 或 `wheel` 提权。

CentOS GenericCloud 等镜像可能只在 `cloud.cfg` 中声明 `cloud-user`，磁盘内尚无该账户。该场景会在离线初始化阶段直接创建 `cloud-user`，不再依赖首次启动时的 cloud-init 创建动作。

## 已有异常虚拟机

修复只影响后续克隆。已经创建且只能使用 root 登录的虚拟机不会被自动修改，避免在运行态改写账户。建议先关机后执行离线账户修复，或删除后从原模板重新克隆；删除、重装等敏感操作仍需二次验证。
