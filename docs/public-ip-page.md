# 公网 IP 页（新前端）

> 对应路由：`/public-ip`（仅管理员）
> 源码目录：`web/src/views/public-ip/`
> 旧版对照：`web-backup/src/views/public-ip/index.vue`

## 功能总览

| 功能 | 说明 |
|------|------|
| 角色限制 | 仅管理员可访问（页面内非管理员显示无权限提示，与模板页一致；后端接口由 AdminMiddleware 保护） |
| 页头操作 | 刷新 / 重载规则（高风险确认，提交任务队列）/ 从网卡导入 IPv6 前缀 / 新增公网 IP |
| 顶部提示 | 绑定、解绑、迁移触发高风险验证并走任务队列；IPv6 路由模式使用 Proxy NDP，每台 VM 分配独立 `/128` |
| 筛选 | 公网 IP 搜索、IP 版本、状态筛选（已绑定/空闲/保留）、模式筛选（1:1 NAT/经典网络-路由/经典网络-桥接），客户端分页 100 条/页 |
| 列表 | 公网 IP、掩码/网关、出口网卡、支持模式（标签）、状态、绑定 VM（名称+模式/用户/私网/运行态）、备注 |
| 行内操作 | 高频「绑定」（空闲）/「迁移」（已绑定）图标外露；其余收进 ⋯ 下拉：编辑、预览/试算规则、解绑（已绑定，危险）/删除（未绑定，危险） |
| 批量操作 | 勾选行后顶部出现批量操作工具栏，支持批量绑定（仅未绑定）/批量解绑（仅已绑定）/批量删除（已绑定自动跳过）；批量绑定弹窗统一选择用户/虚拟机/模式，IPv6 自动剔除 NAT |
| 新增/编辑 | 同时接受 IPv4/IPv6；IPv6 仅提供路由/桥接模式；动态导入地址的 IP、CIDR 与出口网卡由前缀同步器维护；新增支持「单条/批量」切换，批量模式一行一个 IP，其余字段对整批共用 |
| 绑定/迁移 | 用户 → 虚拟机联动过滤；IPv4 NAT 需要私网 IP，IPv6 路由模式无需私网 IP；可先预览规则再提交任务 |
| 规则预览 | 已绑定行直接预览当前绑定关系规则（nftables/路由命令 + 配置提示 + 警告）；未绑定行进入绑定弹窗试算 |
| 解绑/删除/重载 | confirmModal 确认后执行；解绑/重载提交任务队列后延迟 1.2s 刷新列表 |

## 涉及接口（均为管理员）

- `GET/POST /network/public-ips`、`PUT/DELETE /network/public-ips/:id`：公网 IP 资源管理
- `POST /network/public-ips/batch`：批量新增公网 IP，`ips` 数组 + 共用字段，逐条独立校验，批内重复或数据库已存在的自动跳过
- `DELETE /network/public-ips/batch`：批量删除公网 IP（高风险，`ids` 数组），已绑定的自动跳过，部分失败不影响其他 IP，返回每条结果与汇总
- `POST /network/public-ips/batch/bind`：批量绑定公网 IP（高风险，任务队列），`items` 数组每项含 `public_ip_id` 与 `bind_request`，逐条绑定后统一应用规则一次
- `POST /network/public-ips/batch/unbind`：批量解绑公网 IP（高风险，任务队列），`ids` 数组，逐条解绑后统一应用规则一次
- `GET /network/public-ips/ipv6-prefixes`：按指定网卡探测公网 IPv6 前缀；`uplink_if` 留空时读取 IPv6 默认路由
- `POST /network/public-ips/ipv6-prefixes/import`：从已探测前缀确定性生成指定数量的独立 `/128` 资源
- `POST /network/public-ips/:id/preview`：绑定规则预览（试算）
- `POST /network/public-ips/:id/bind`、`/unbind`、`/migrate`：绑定/解绑/迁移（高风险 428 二次验证，任务队列异步应用）
- `POST /network/public-ips/apply`：按当前绑定关系重载全部规则（高风险）
- `GET /user/list`、`GET /vm/list`：绑定弹窗的用户与虚拟机选项

## 批量新增公网 IP

新增公网 IP 弹窗的「公网 IP」栏右侧提供「单条 / 批量」切换（仅新增模式可见，编辑模式保持单条编辑）。

- **单条模式**：与原有一致，单个 IP 输入框。
- **批量模式**：切换为多行文本框，一行一个公网 IP；下方 CIDR、网关、出口网卡、支持模式、状态、备注等字段对整批 IP 共用。
- 提交时前端按行拆分、去空、去重后一次性调用 `POST /network/public-ips/batch`；后端逐条独立校验（IPv6 自动剔除 NAT 模式），批内重复或数据库已存在的 IP 自动跳过，不会覆盖已有记录。
- 返回结果汇总成功、跳过、失败数量；失败条目附带原因（如 IP 格式无效、网关与 IP 地址族不一致等）。
- 适合一次录入同网段的多个 IPv4/IPv6 地址，例如运营商分配的一段 IPv6 `/64` 下逐个 `/128`。

## 批量操作（绑定 / 解绑 / 删除）

公网 IP 列表支持行选择与批量操作。勾选行后，表格上方出现批量操作工具栏，显示已选数量与可操作数量。

- **批量绑定**：仅未绑定的行可参与（已绑定的会自动排除）。点击「批量绑定」打开批量绑定弹窗，统一选择用户/虚拟机/模式，IPv4 NAT 模式可填写统一私网 IP（留空时后端按所选 VM 自动解析）。选中项含 IPv6 时自动剔除 1:1 NAT 模式。提交后由任务队列异步应用，逐条绑定后统一应用规则一次。
- **批量解绑**：仅已绑定的行可参与。点击「批量解绑」后二次确认，提交任务队列逐条解绑并统一应用规则。
- **批量删除**：所有选中行都可参与。已绑定的会自动跳过（不会删除），部分失败不影响其他 IP。同步返回每条结果与汇总。
- 批量绑定/解绑均为高风险操作，触发 428 二次验证并走任务队列，提交后延迟刷新列表。
- 批量操作只提交一个任务（而非每条 IP 一个任务），避免任务队列被打满；任务内逐条执行，部分失败会记录在结果里但不中断其他条目。

## IPv6 工作方式

1. 宿主机上联网卡需已通过 RA 或静态配置获得公网 IPv6 地址和默认路由。页面点击“导入 IPv6 前缀”，默认自动选择 IPv6 默认路由网卡。
2. 导入操作不会把生成地址直接添加到宿主机，而是登记为可分配资源；同一前缀重复导入会跳过已有地址。
3. 绑定到非直通交换机后，宿主机为 VM 安装精确 `/128` 路由，在上联网卡登记 Proxy NDP，并仅放行该 VM 的精确 IPv6 源地址。该方案不使用 NAT66。
4. Linux VM 已运行且 QEMU Guest Agent 提供命令执行能力时，面板会自动识别主网卡 MAC，配置公网 IPv6 `/128` 与链路本地默认网关，并安装 `qvm-public-ipv6.service` 持久化到后续启动。VM 关机或 Guest Agent 暂未就绪时显示“等待自动配置”，后台周期重试；其他来宾按绑定结果中的参数手动设置。
5. 动态公网前缀按“系统设置 → 存储与网络 → 公网 IPv6 前缀同步周期”检测。前缀变化时保留每个资源的主机位，原位更新资源、绑定快照、Proxy NDP、路由、VPC ACL 与端口安全策略。

## IPv4 路由模式

经典网络-路由适用于运营商将单个公网 IPv4 或公网段交付给宿主机、但 VM 仍接入面板私网交换机的场景。绑定后，宿主机为公网地址创建指向 VM 私网地址的 `/32` 精确路由；若上游以 ARP 方式交付该地址，出口网卡同时启用 Proxy ARP。

- Linux VM 保留原有 DHCP 私网地址作为宿主机下一跳，并在同一主网卡添加公网 IPv4 `/32`。
- VM 默认路由仍指向私网网关，但路由首选源地址必须为已绑定公网 IPv4，不能将跨网段的运营商网关直接配置为 VM 默认网关。
- 运行中的 Linux VM 且 QEMU Guest Agent 提供命令执行能力时，面板会自动安装 `qvm-public-ipv4.service`，将已绑定公网 IPv4 `/32` 和带公网源地址的默认路由持久化；绑定、解绑、迁移、规则重载及面板启动后的后台重试都会同步。Windows 或 Guest Agent 不可用的来宾仍需手动配置。
- 防伪造策略同时放行该 VM 的私网下一跳地址和已绑定公网地址，避免阻断宿主机的 ARP 邻居解析。
- 经典网络-桥接仅适用于上游交换机允许 VM MAC 直接接入的二层交付；不具备该条件时应使用经典网络-路由或 1:1 NAT。
- 宿主机将物理出口迁入 OVS 直连桥后，资源记录仍可保留原物理网卡名。运行时会自动识别承载宿主机公网地址和默认路由的 OVS 内部口，并在该接口应用 NAT、Proxy ARP、Proxy NDP 与转发规则；无需重新录入公网 IP 资源。

### 限制与注意事项

- 自动导入使用上联网卡已有的公网前缀，不等同于 DHCPv6-PD；当前上游若只下发一个 `/64`，由宿主机通过 Proxy NDP 将独立 `/128` 路由给 VM。
- IPv6 不提供 1:1 NAT 模式。经典桥接模式要求上游二层网络直接可达 VM；普通 VPC/系统网络推荐使用经典路由模式。
- VPC 安全组按地址族分别编译。添加规则时选择“IPv6”，来源可填写 IPv6 CIDR（例如 `::/0`），并可选择 TCP、UDP、ICMPv6 或全部协议；仅有 IPv4 规则时不会放行公网 IPv6。
- 绑定列表会显示“来宾 IPv6”状态与原因。解绑或迁移时，面板通过 Guest Agent 删除由本模块登记的旧 `/128` 和默认路由，不触碰来宾的其他 IPv6 地址。
- `conntrack -D` 在没有匹配连接时会以退出码 1 返回“0 flow entries”；清理逻辑使用静默命令处理该正常空结果，不再写入错误日志。
- 清理已有 `iptables` / `ip6tables` 规则时强制使用数字地址输出，避免反向 DNS 解析异常导致绑定、解绑或规则重载任务超时。
- 删除、绑定、解绑、迁移和规则重载仍保留二次验证；绑定相关运行时变更仍进入任务队列。

## 与旧版差异

1. **移动端卡片移除**：旧版表格 + 移动端卡片双视图，新版统一为响应式表格（小屏横向滚动），与网络页策略一致。
2. **行内操作收折**：旧版 6 个文字按钮平铺，新版按「纯图标 + Tooltip + ⋯ 下拉」规范收折（仅高频绑定/迁移外露），危险项（解绑/删除）置底并标红。
3. **状态/模式标签色彩**：状态标签（已绑定绿/保留橙/空闲灰）与模式标签统一 Semi Tag 配色，替代 Element Plus type 映射。
4. **编辑约束前置**：已绑定行的 IP 与状态字段在表单内禁用并附提示（旧版仅依赖后端报错）。
5. **数据加载语义保持**：进入页面并行加载公网 IP 列表 + 用户列表 + VM 列表；任务提交后延迟刷新语义与旧版一致。
