# ESXi 风格虚拟交换机与软路由使用说明

## 模式说明

交换机在创建时直接选择零或一个物理上行链路：

| 上行链路 | 内置 DHCP | 模式 | 典型用途 |
|---|---:|---|---|
| 未绑定 | 关 | 空交换机 | 软路由 LAN、虚拟机内部二层网络 |
| 物理网口 | 关 | 物理直通 | 虚拟机接入上级交换机、路由器或 VLAN |
| 物理网口 | 开 | 内置 DHCP/NAT | 由面板提供私网地址、网关、DNS 与 NAT |

系统基础网络继续使用系统出口和公共 DHCP/NAT。普通用户可选择系统基础网络，也可创建自己的空交换机；物理上行和内置 DHCP/NAT 由管理员配置。

## 使用软路由组网

以爱快、OpenWrt 等软路由为例：

1. 管理员创建一个物理直通交换机，将软路由 WAN 网口接入；也可以直接把 WAN 接入系统基础网络或托管交换机。
2. 创建一个不绑定上行、关闭内置 DHCP 的空交换机。
3. 为软路由添加第二张网卡作为 LAN，并接入空交换机。
4. 将需要由软路由管理的虚拟机网卡接入同一空交换机。
5. 在软路由中开启 LAN DHCP、DHCPv6 或 RA，并配置需要的 NAT、DNS 和防火墙。

空交换机不会创建宿主机三层地址、dnsmasq 或 NAT，也不会应用安全组、源地址限制、DHCP/RA 拦截。宿主机和外部网络默认不可从此交换机访问；交换机流量和带宽配额仍会执行。

## 物理直通注意事项

- 第一版每个交换机只绑定一个物理网口。
- 同一个物理网口只接入一个 OVS 直通网桥；多个二层直通交换机可共享该网桥。可保留一个 VLAN ID 0 的无标签交换机，其余交换机必须使用互不重复的非零 VLAN ID。托管 NAT 不重复接管物理口，可以复用该直通网桥上的宿主机三层出口。
- VLAN ID 为 `0` 时不打标签；`1-4094` 时虚拟机网口携带对应 VLAN 标签接入上级网络。
- 删除或重配置首个直通交换机时，面板会把共享网桥的运行态所有权移交给同物理口上的其它直通交换机，不会中断或误删仍在使用的共享网桥。
- 如果所选网口承载宿主机 IPv4、默认路由或 DNS，需要开启“迁移宿主机 IP”。系统会保存地址、网关、路由 metric 与 DNS，迁移到交换机 OVS 网桥；切换离开或删除交换机时自动回迁。
- 宿主机网络变化属于高风险操作，提交前需完成二次验证。

## 托管 DHCP/NAT

托管模式要求物理上行的有效三层接口具有 IPv4 地址。系统会自动读取该接口的默认网关；接口有地址但未安装默认路由时，可在交换机表单填写“上行网关”。系统为每个交换机分别创建：

- `br-ovs` 上的 VLAN 网关端口；
- 独立 dnsmasq 配置、地址池与租约；
- NAT 与 FORWARD 规则；
- 以交换机 CIDR 为源、以交换机 ID 派生表号的策略路由。

策略路由确保指定的非默认物理网口成为真实出口。多个托管交换机可以共享同一个物理出口，也可以使用已有物理直通交换机的 OVS 网桥作为有效三层出口；预检会拒绝缺少地址或既未检测到也未填写上行网关的接口。

关闭内置 DHCP 时，数据库保留原 CIDR、网关和地址池，下次开启可直接复用，但关闭期间不会运行网关、dnsmasq、NAT 或策略路由。

## 在线重配置与回滚

拓扑编辑通过 `POST /vpc/switches/:id/reconfigure` 提交 `vpc_switch_reconfigure` 任务。任务流程为：

1. 预检目标上行占用、IPv4 地址、网关、VLAN 和地址池。
2. 准备目标网桥或托管运行态。
3. 按虚拟机名称和逻辑网口序号逐个替换网口网络，保留 MAC、型号、Open vSwitch interface ID、带宽和其他 XML 字段。
4. 保存交换机目标状态，清理旧 dnsmasq、NAT、策略路由或独立网桥。
5. 刷新带宽、ACL 与端口安全。

任一步失败时，任务按相反顺序恢复已处理网口和旧运行态。来宾或 libvirt 不支持热拔插时会恢复原网络，任务消息提示关机后重试。

## 历史交换机迁移

升级不会自动改变历史用户 NAT 交换机。它们继续按旧运行态工作，并在交换机列表中标记为待迁移。管理员可在 `⋯` 菜单选择“迁移为空交换机”，确认关联虚拟机后提交同一异步重配置任务。

迁移成功后旧 dnsmasq、NAT、FORWARD 和策略路由被清理，全部关联网口接入新的独立 OVS 网桥。系统基础网络和历史桥接直通记录不进入此迁移。

## 常用检查命令

```bash
ovs-vsctl show
ovs-vsctl list-br
ovs-vsctl list-ports <bridge>
virsh domiflist <vm>
ip -4 rule show
ip -4 route show table <100000+switch_id>
iptables -t nat -S
```

删除或切换前建议记录宿主机当前地址与路由：

```bash
ip -4 -o addr show
ip -4 route show default
resolvectl status
```
