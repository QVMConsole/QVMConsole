# 硬件直通设备扫描性能优化

## 背景

宿主机 PCI 设备较多时，逐个执行 `virsh nodedev-dumpxml` 和 `lspci` 会产生大量子进程。详情页的 SSE 通知每 3 秒到达一次，如果每次通知都触发扫描，会让扫描任务重叠并放大 libvirt 与系统命令负载。

## 当前行为

- 虚拟机详情 SSE 更新不会重新扫描宿主机 PCI 设备。
- 进入“硬件直通”标签页或打开直通选择器时才按需加载设备列表。
- 前端同一表单及不同表单实例会复用同一进行中的请求。
- 后端使用 10 秒短 TTL 缓存；缓存过期后先返回旧快照，再由单个后台任务刷新。
- 服务开始监听后异步预热缓存，不阻塞其它启动流程。
- 绑定、解绑、添加或移除直通设备后会使缓存失效并后台刷新。
- 扫描优先执行一次 `lspci -D -mm -nn`，结合 sysfs 读取驱动和 IOMMU 组；仅在 `lspci` 不可用时回退到旧的逐设备兼容路径。

## 运维验证

查看命令日志时，正常情况下同一时间最多应有一个直通扫描任务，且不再周期性出现成百上千条 `virsh nodedev-dumpxml` / `lspci` 子进程。打开直通页面后可观察 `/host/passthrough` 首次请求及后续 10 秒内请求耗时明显下降。

本优化未新增 apt 或第三方依赖。
