# OVF / OVA 虚拟机导入与导出

## 功能范围

虚拟机创建向导提供四个独立入口：使用 ISO 镜像安装、从模板快速克隆、导入已有磁盘、导入虚拟机。

“导入已有磁盘”继续处理 QCOW2、RAW、VMDK、VHD/VHDX、IMG 等单磁盘镜像；“导入虚拟机”只处理 OVF/OVA，并读取包内硬件描述、全部磁盘和逻辑网卡。

## 导入虚拟机

### 准备文件

- OVA：上传单个 `.ova` 文件到“我的存储 → 虚拟磁盘”。
- OVF：将 `.ovf`、其实际引用的 VMDK 等磁盘以及可选 `.mf` 清单上传到同一虚拟磁盘目录。OVF 引用只接受安全的同目录文件名。
- 管理员也可选择绝对路径；普通用户仅能选择自己的虚拟磁盘目录。

### 操作步骤

1. 打开“新建虚拟机”，选择“导入虚拟机”。
2. 在虚拟机包页选择配置方式：
   - **跟随 OVF 配置**：创建任务采用包内 CPU、内存、固件、机型、磁盘总线和网卡型号；网络自动映射本机默认交换机及安全组，选择文件后可直接点击“按 OVF 配置创建”。
   - **自定义**：选择文件后直接进入完整向导，由表单配置覆盖包内硬件、目标存储、网络和高级选项，最后在确认页提交。
3. 选择源文件保留策略及导入后是否启动；自定义模式还可调整开机自启等后续配置。

创建向导不再重复读取虚拟机包。两种方式都会立即提交异步任务，归档安全、清单、架构、空间和配额校验统一在任务中完成。

导入使用独立 `import_appliance` 任务。任务依次校验包和空间、转换全部磁盘、定义虚拟机、连接全部设备、应用网络映射并按选项启动。任一步骤失败或任务取消都会清理虚拟机定义、已生成磁盘和临时文件，源包保持不变。

提交接口只执行来源参数、虚拟机名称和本机网络等快速检查，随后立即返回任务 ID。归档安全检查、清单校验、架构检查、临时空间检查、全部磁盘容量统计和用户配额复核在 `import_appliance` 任务中执行，避免大体积 OVA 阻塞请求。

`copy_source=false` 时，仅在完整成功后删除源文件：OVA 删除单个包；OVF 删除描述、清单和本次实际引用的配套磁盘。

### 安全与兼容边界

- 支持 OVF 1.x/2.x 常见硬件描述，导出生成 OVF 1.0 兼容描述。
- 拒绝路径穿越、外部引用、链接或特殊文件、重复文件名、异常文件数量和异常展开大小。
- 存在清单时校验 SHA-1 或 SHA-256；QVMConsole 导出清单固定使用 SHA-256。
- 已知包架构与宿主机架构冲突时终止任务；缺失架构时使用宿主机默认值。
- 包内全部声明磁盘都会导入，不能在导入阶段跳过单块磁盘。

## 标准 OVA 导出

1. 先关闭虚拟机。
2. 在虚拟机列表的更多菜单中选择“导出虚拟机”。
3. 选择“标准 OVA 虚拟机”。系统盘固定勾选，数据盘默认全选且可取消。
4. 提交后在任务中心查看进度；结果保存为“我的存储 → 虚拟磁盘”中的单个 `.ova` 文件。

导出会展平所选磁盘的 backing chain，转换为 `streamOptimized` VMDK，生成 OVF 描述及 SHA-256 清单，再封装为 OVA。任务不会自动改变虚拟机电源状态。

OVF 会逐盘记录 `virtio`、SCSI、SATA 或 IDE 总线及对应控制器，导入时按原配置恢复。对早期面板导出的 OVA，检查阶段会根据保留的 `vda`/`vdb` 设备名恢复 VirtIO 总线，避免 UEFI 固件跳转到 PXE。

以下内容不进入 OVA：ISO、软盘、快照树、原 NVRAM、保存态、宿主机直通设备。导入目标会重新使用本机固件文件、网络映射和 MAC 地址。

原“QCOW2 磁盘”导出保持兼容；请求省略 `format` 时仍按 QCOW2 处理。

## 存储、配额与临时目录

- `.ova`、`.ovf`、`.mf` 支持上传、断点续传、下载和删除，均计入我的存储 project quota。
- OVA 导出以非 root 身份写入虚拟磁盘目录：普通账号优先使用同名系统用户，管理员等仅存在于面板的账号使用 QEMU/libvirt 服务用户，project quota 会在实际写入时再次强制限制。
- 导入任务开始阶段根据虚拟机包全部声明磁盘容量复核用户资源配额。
- 系统设置中的“虚拟机包临时目录”用于 OVA 解包、VMDK 转换和封装；环境变量为 `KVM_APPLIANCE_TEMP_DIR`，默认位于模板目录的 `_appliance` 子目录。
- 导入和导出任务开始前会检查临时目录可用空间，失败或取消会清理工作目录和 `.partial` 文件。

## API

检查接口（只读，供 API 调试或独立预览使用，创建向导不调用）：

- `POST /self/vm/import-appliance/inspect`
- `POST /vm/import-appliance/inspect`

导入接口（异步任务，保留 `create_vm` 二次验证）：

- `POST /self/vm/import-appliance`
- `POST /vm/import-appliance`

导入载荷中的 `config_mode` 使用 `ovf` 或 `custom`：`ovf` 在任务解析后应用包内配置，`custom` 保留请求提交的硬件与网络配置。省略该字段时按旧版 `custom` 行为处理。

导出接口：

- `GET /self/vm/:name/export-options`
- `POST /self/vm/export`

导出请求示例：

```json
{
  "vm_name": "vm-example",
  "format": "ova",
  "disk_devices": ["vda", "vdb"]
}
```

上述新接口支持账号会话和 API Key；导入提交仍执行高风险二次验证。

## 任务排查

- “配套磁盘不存在”：确认 OVF 的 `ovf:href` 文件与 OVF 同目录且文件名完全一致。
- “完整性清单校验失败”：重新上传未被修改的描述、磁盘和清单。
- “架构不一致”：在相同架构的宿主机导入该包。
- Windows 导入提示 `<clock>` 与 `<features>` 标签不匹配：更新后重新提交任务；新版会在调用 libvirt 前校验生成的 domain XML，并清理失败任务产生的目标磁盘和 NVRAM。
- “临时空间不足”：调整 `KVM_APPLIANCE_TEMP_DIR` 到容量更大的本地文件系统。
- “存储配额不足”：清理“我的存储”文件或调整用户存储配额后重新提交。
